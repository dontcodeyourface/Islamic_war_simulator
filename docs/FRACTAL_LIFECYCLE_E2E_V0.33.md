# Fractal lifecycle E2E v0.33

**Status:** implementation/validation milestone  
**Depends on:** v0.24 materialization, v0.28 autonomous regional regimes, v0.29 graph projection, v0.30 regional spillover, v0.31 parent-child coupling, v0.32 conservative reaggregation, canonical L2 catalog.

## Canonical lifecycle

The required lifecycle is:

`L1 -> refine -> materialize L2 generation 1 -> autonomous divergence -> interaction -> recovery/consensus -> conservative collapse -> L1 -> later re-refine -> L2 generation 2`.

Resolution follows stress. While L2 is active, regionalizable dynamics are owned by active children. The L1 parent remains available for lineage, national-only state, aggregation and cross-scale coordination; it must not execute the same regionalizable causal mechanism in parallel.

## Geography

Production-facing lifecycle tests use the explicit canonical L2 catalog. Spain therefore materializes its 19 first-order children rather than anonymous `R1/R2` placeholders. Synthetic three-child fixtures remain only where a unit test is specifically testing an algebraic or lifecycle invariant independent of geography.

The regional graph resolves only evidence-backed administrative land adjacency in this milestone. Missing strategic channels remain null/unresolved. Administrative membership or identity never creates trade, migration, information, criminal, extremist or alliance weights.

## Collapse contract

Collapse consumes the live child state, not the original split. Additive regionalizable stocks are reconstructed conservatively; intensive/latent values follow the configured aggregation rule; national-only state remains owned by L1. Categorical regimes require sibling consensus and fail closed on disagreement.

Successful collapse closes every active sibling with a de-refinement day, removes active child EngineState from the child store, resets refinement persistence to L1, and retains the closed topology lineage immutably.

## Re-refinement contract

A later expansion must materialize a new generation through the production materializer. Closed generation-1 node IDs are never reactivated. Stable catalog identity is preserved while runtime identity advances to `<catalog_child_id>::g2`. Generation 1 remains inactive and byte-for-byte unchanged.

## Validation map

- `test_fractal_region_catalog.py`: canonical parent/child coverage, counts, namespace, positive normalized weights, provenance, stable catalog IDs.
- `test_fractal_region_graph_catalog.py`: graph endpoints, duplicate/self-edge rejection by fixture invariant, terrestrial component closure, unresolved strategic-channel discipline.
- `test_fractal_regional_day.py`: canonical Spain materialization and autonomous sibling divergence under real child IDs.
- `test_fractal_reaggregation.py::test_collapse_accepts_autonomous_child_dynamics_and_uses_live_state`: collapse uses evolved child state.
- `test_fractal_reaggregation.py::test_dynamic_collapse_then_rerefine_preserves_generation_lineage`: real collapse followed by production generation-2 materialization, stable catalog identity and immutable generation-1 history.

## Determinism and traceability

Topology, child store, projected graph and commit records remain hash-addressed. Materialization and collapse record action IDs, policy IDs, source variables, catalog provenance and before/after hashes. Identical manifest, configuration, state and seeds must reproduce identical lifecycle objects.

## Deferred

This milestone does not infer unresolved regional strategic channels and does not recursively promote L2 children into L3. L3/L4/L5 generalization follows only after the canonical L2 lifecycle is validated end to end.

No tactical route planning, target selection, weapon selection or operational execution is introduced by this lifecycle.
